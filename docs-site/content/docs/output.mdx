---
title: Output and formats
description: JSON by default, a table when you want to read it, JSONL when you want to pipe it.
---

Commands use JSON by default. `chat open` is an interactive text session unless you select
`--format jsonl`. Errors go to stderr rather than stdout.

```bash
wallapop search "bici" | jq '.items[0]'
```

## Formats

<Tabs items={['json', 'pretty', 'jsonl', 'toon']} id="format">
  <Tab value="json">
    The default format prints one JSON document.

    ```bash
    wallapop search "bici"
    ```
  </Tab>
  <Tab value="pretty">
    It prints a compact table for reading in the terminal: hash, price, flags, title, city, URL.

    ```bash
    wallapop search "bici" --format pretty
    ```
  </Tab>
  <Tab value="jsonl">
    It prints one object per line, for streams and pipes. Use it for incoming chat messages or watch events.

    ```bash
    wallapop chat open 8f1c2 --format jsonl
    ```
  </Tab>
  <Tab value="toon">
    It prints TOON output for language-model context.

    ```bash
    wallapop search "bici" --format toon
    ```
  </Tab>
</Tabs>

Colour follows `NO_COLOR` and switches off when stdout is not a terminal.

## Errors

Errors are human-readable by default. For scripts, ask for the envelope:

```bash
wallapop --error-format json item show zzzzzzzzzzzz
```

```json
{
  "code": 4,
  "category": "not_found",
  "message": "no item with that hash",
  "endpoint": "GET /api/v3/items/{hash}",
  "suggested_commands": ["wallapop search ..."]
}
```

The `category` is stable and worth branching on. The prose in `message` is not.
