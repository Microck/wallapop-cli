<Callout type="info" title="Release binaries">
  Release builds include the pinned Galleton session engine. No separate daemon installation
  is required. Releases ship `checksums.txt` with a GitHub provenance attestation.
</Callout>

## Installer

Installs the latest release into `~/.local/bin` (override with `WALLAPOP_INSTALL_DIR`):

```bash
curl -fsSL https://wallapop.micr.dev/install.sh | sh
```

## Homebrew

```bash
brew install Microck/tap/wallapop
wallapop --version
```

## Scoop

```powershell
scoop bucket add microck https://github.com/Microck/scoop-bucket
scoop install microck/wallapop
wallapop --version
```

## npm

```bash
npm install -g wallapop-cli
wallapop --version
```

The postinstall step downloads the matching release archive for your platform, checks its
SHA-256 against `checksums.txt`, and installs the binary.

## Arch Linux

```bash
yay -S wallapop-cli-bin
wallapop --version
```

The package covers Linux amd64 and arm64, verifies the checksum and installs the binary.

## Go install

```bash
go install github.com/Microck/wallapop-cli/cmd/wallapop@latest
wallapop --version
```

A plain Go install builds the pinned engine on first authenticated use, using the Go
toolchain and module cache. An uncached module needs download access once. To include the
engine before installation, clone the repository and run `make install`; release binaries
also work without Go or an engine download at runtime.

## Check it works

```bash
wallapop --version
wallapop doctor
```

`doctor` checks that the config parses, the session mints, Wallapop is reachable and the CLI
can fetch the chat token. Run it first whenever something behaves oddly.
